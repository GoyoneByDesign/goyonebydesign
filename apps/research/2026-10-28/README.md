## View4Real: international evidence, not a replacement solver

Read the existing reader-adaptability and research-context records first. Prior Pyolimp, ChromaCorrect, FIU, Montalto, Tanaka/Kawano and Berkeley leads are not new discoveries.

- [Kyushu Institute of Technology / JST Japanese slides, December 9, 2021](https://shingi.jst.go.jp/pdf/2021/2021_kyutech_006.pdf): simulated visual reproduction and image-quality metrics do not establish human eyesight correction. The slides identify human experiments as future work and disclose patent application 2021-014469. This is additional evidence within an existing research family, not a new 2026 result or reuse/license clearance.
- [Chinese journal abstract: fast deconvolution for myopia/hyperopia in head-mounted displays](https://www.jcad.cn/article/id/5cb49030-5bf3-494b-8af1-50675a9f58cb?viewType=citedby-info): the HMD setting and abstract-level algorithm description are not ordinary-monitor or independent per-eye validation. No reproducible implementation was established here; publication recency is not claimed.
- [Dual-input neural image precompensation](https://www.mdpi.com/2313-433X/12/9/456): revisited publisher-indexed text describes normal-vision participants judging simulated retinal images, not correcting their own eyesight. Direct full-text retrieval returned 429; no experiment reproduced. Keep held-out PSF and model-mismatch tests as prerequisites rather than relying only on matched-model scores.
- [Nagoya Institute university record for binocular display correction](https://pure.nitech.ac.jp/en/publications/binocular-visual-distortion-correction-on-display/): publication is established, but full publisher PDF retrieval returned 403. Participant protocol and ordinary-display hardware efficacy remain unverified in this review.

**Decision:** retain the current bounded optical laboratory and neutral reader defaults. A shared ordinary display is not independent left/right image control; prescription alone does not calibrate all optical conditions. Any later candidate must compare normal, enlarged and sharpened baselines at matched display constraints, report each eye and worst-eye regression, clipping, contrast, runtime and PSF/pupil/distance mismatch, and be rejected if worse. Real-browser reader acceptance, calibrated optical and human validation remain separate gates. No supported prescription range, clinical safety or glasses-replacement claim follows.

## StockPilot: recovery must preserve operational fences

This is a new focused recovery review for the separate read-only Worker schema, not a repeat of completed Node shutdown or synthetic-proof work. [Cloudflare D1 limits](https://developers.cloudflare.com/d1/platform/limits/) (updated October 24) specify **7 days** of point-in-time recovery on Free versus 30 on Paid, and a 100 KB SQL-statement limit. The [Time Travel documentation](https://developers.cloudflare.com/d1/reference/time-travel/) describes recovery on supported production storage; this is not evidence that an account or database has been verified here.

[Official import/export documentation](https://developers.cloudflare.com/d1/best-practices/import-export-data/) says exports use SQL and block other database requests while running. Its documented statement-size limitation matters to the current 512 KiB maximum JSON observation: a naive literal INSERT of a large snapshot is not automatically a proven restorable backup. No export, restore, database, R2, Workflow or permission was created.

**Engineering inference / retained deployment gate:** restoring a database can rewind the read-only job checkpoint, lease and daily budget along with observations. A production recovery procedure therefore needs disabled scheduling/provider reads during recovery, isolated synthetic restore tests, explicit stale/recovered status, account-scope verification and protection against replaying an old daily budget. Do not infer that Time Travel alone satisfies these application invariants. The existing source remains disabled and undeployed; no operational data currently requires migration by this review. No hurried runtime patch or build 14 is warranted without a defined recovery contract and acceptance tests. Approved seller consent, protected origin and dedicated database configuration are still pending, not granted by this automation.

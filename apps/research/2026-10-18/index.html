Display research: dated evidence, unchanged recommendation

English, Japanese and Chinese primary-source searches and date checks found no newly verified controlled ordinary-screen human result warranting a release change since October 17. This is a bounded search, not proof that no advances exist.

Alkzir/PyOLimp remains the known September 20, 2026 baseline. Its human comparison used simulated retinal images rather than individually matched real-eye correction. Reported 512-by-512-image runtimes include USRNet-PC at 0.975 seconds on GPU and DWDN-PC at 5.644 seconds on x86 and 118.331 seconds on ARM; those figures are not live-display rates. The study uses fixed pupil/image assumptions and leaves mismatch robustness unresolved. The MIT license at the code repository's top level does not settle every model-weight or dataset right. The linked dataset was published July 15, 2025, not September 2026; its license field did not establish reuse rights in the checked record. Paper, code, dataset

Previously reviewed methods are not relabeled new. The inverse-filtering preprint remains version 1 submitted December 30, 2024; a 2026 date on an HTML rendering does not make it a new submission. Its SSIM result measures reconvolved images, not eyesight improvement. Ringing, tile seams and differing-eye requirements remain limitations. Nagoya's VISAPP 2026 binocular model remains simulation evidence. ChromaCorrect, Huang, Montalto, Tanaka/Kawano and yesterday's SharpView Font review remain earlier comparisons.

Newly checked older hardware-only background: Liu and colleagues' Alvarez-lens near-eye display, published November 12, 2025, uses physical displaced lenses. Peng and colleagues' metalens-array light-field study, published June 12, 2026, reports simulation and data available on request. Akpinar and colleagues' wavefront-coding work, submitted October 14, 2025, uses a custom diffractive optical element and neural processing. These are additional background sources, not October 18 inventions or ordinary-screen software deployment evidence.

TDK watchlist refresh: the Japanese CEATEC page lists its meta-optic mirror as under development and records an award. The press index dates the award announcement to October 6; the October 2 release still describes a monochrome prototype with full-color production in the future. This is not a new October 18 human reading-benefit result. Apple's September 16 Japanese digital-prism guidance concerns supported prescriptions in a separate-display Vision Pro headset, not sphere/cylinder correction on a shared ordinary screen.

Decision: add no model, font, paper asset, camera access or dependency. Preserve the original-image bypass, semantic text and accessible enlargement. Future bounded synthetic work should record physical scale, pupil/distance assumptions, per-eye outcomes, clipping, contrast, halos, mismatch, runtime and cancellation, using unchanged text and ordinary sharpening as baselines. Previously recorded negative cases remain valid. Optical-bench forward validation and appropriate controlled reading-accuracy, speed and comfort evaluation remain missing gates. Screenshots, SSIM and informal preferences cannot establish glasses replacement.

MAX-ALPHA: request and response contracts

The current public worker source still requests gemini-3.5-flash-lite with temperature 0, candidateCount 1 and maxOutputTokens 512. Google's migration guide, updated October 13, still says sampling parameters are deprecated/ignored and candidate_count is unsupported for Gemini 3 and later. This is the existing October 16/17 compatibility candidate, not a newly observed outage. The final request turn is already a user turn.

The current REST response reference also documents CONTINUATION: generation is incomplete and continuation would require another request. This review newly checked that contract; it does not establish when that behavior first appeared or whether the configured model emits it. Static source inspection shows MAX-ALPHA accepts only STOP, rejects MAX_TOKENS and other finish reasons, handles prompt blocks/empty text, and has no automatic continuation. It does not silently treat these partial responses as success.

Next engineering candidate: no-network fixtures covering complete, blocked, empty, truncated, CONTINUATION, unknown-finish, malformed, cancelled and failed responses, plus the exact request fields. Preserve authentication, the one-question/no-history boundary, model selection, limits and no automatic retry or paid fallback. No fixture was executed and no provider request was made today.

Android: signing and reminder reliability

Android's signing guide, last updated March 6, 2026, distinguishes the installed app-signing key from a Play upload key. Resetting an upload key is not a general way to replace the signing identity of an existing sideloaded installation. No applicable managed signing-key recovery route has been established for the old JustMyPick/SavvyKin package. Do not uninstall or clear the existing app to bypass an upgrade failure.

For StatusPing, Android 15's stopped-state behavior cancels pending intents on force-stop; direct or indirect user interaction is needed to leave that state. The alarm guide also documents alarms being canceled at device shutdown and the separate rescheduling path after boot. These are existing platform rules, not new October 18 features.

Decision: retain the exact-APK test matrix for Doze, reboot, force-stop/reopen, denied/restored permissions, timezone/DST and duplicate prevention. Do not extrapolate emulator source checks to physical-phone reliability, or a local reminder to delivered caregiver messages. No permission, signing, package or device change was made.

Web apps: accessibility, storage and privacy

WCAG 2.2 is an existing W3C Recommendation republished December 12, 2024, not a newly announced standard. Useful future checks across Questrix, The Commissary, BOARDROOM and the owner-facing web apps include keyboard operation and focus visibility, focus not entirely hidden by overlays, reflow at 320 CSS pixels with the defined two-dimensional-content exception, target sizing/spacing and accessible authentication. Test actual sign-in, dialogs, errors and export/restore flows; a visually narrow screenshot does not establish conformance. No WCAG conformance claim is made.

The WHATWG Storage Standard starts local storage buckets in best-effort mode and distinguishes storage-pressure handling from persistent storage. WebKit's storage-policy article dates to August 10, 2023 and was already referenced in earlier reviews. Persistence is not an off-device backup.

Decision: keep owner-only access unchanged. Future isolated checks should cover failed/interrupted writes, concurrent edits, restart, truthful saved/error status and reviewed export/restore using synthetic data. Verify each app's actual storage path instead of assuming browser and server storage are interchangeable. Do not clear Safari data, remove installed web apps, upload private records or expand permissions for an icon or research check.

StockPilot: preserve the completed shutdown repair

The existing source-update history already records version 1.0.3/build 3, 285 local tests and the isolated Windows database-release check. This research does not repeat or supersede that result.

The Node 24.18.0 SQLite reference documents database.close() as a wrapper around sqlite3_close_v2(). SQLite's own contract explains that outstanding statements, blob handles or backup objects can defer actual resource deallocation. This supports retaining the completed shutdown and resource-release regression; an HTTP listener stopping alone is not evidence that database work has finished.

Decision: do not implement the same repair again. Keep the main maintenance channel separate from broader unmerged work. Existing synthetic restore evidence should be reused before proposing duplicate tests. Real provider reconciliation, approved hosting/authentication and production recovery remain separate gates.
